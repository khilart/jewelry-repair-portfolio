# Delta for Repair / Order Labels

## ADDED Requirements

### Requirement: Настройки геометрии этикетки

Размеры ленты задаются один раз на компанию и применяются ко всем этикеткам.
Отдельного справочника форматов нет — в мастерской одна лента.

#### Scenario: Значения по умолчанию

- GIVEN модуль `jewelry_repair_label` только что установлен
- WHEN администратор открывает настройки ремонта
- THEN ширина ленты равна 14 мм, длина этикетки 35 мм, зазор 8 мм, плотность 4, разрешение 203 dpi

#### Scenario: Изменение размеров влияет на печать

- GIVEN администратор изменил длину этикетки или ширину ленты
- WHEN печатается следующая этикетка
- THEN TSPL-программа содержит новые значения в `SIZE` и `GAP`
- AND растр пересчитан под новую печатную ширину

#### Scenario: Печатная ширина кратна байту

- GIVEN любая ширина ленты в настройках
- WHEN рассчитывается ширина растра в точках
- THEN она округляется вниз до кратной восьми, потому что TSPL задаёт ширину в байтах

### Requirement: Содержимое этикетки

Этикетка несёт минимум, достаточный для опознания заказа глазами и сканером.

#### Scenario: Состав этикетки

- GIVEN заказ с номером, клиентом, типом изделия, размером, сплавом и сроком
- WHEN формируется этикетка
- THEN на ней есть QR-код и крупный номер, а под ним клиент, изделие с размером
  и количеством, сплав и срок изготовления

#### Scenario: Формат срока

- GIVEN заказ со сроком изготовления
- WHEN строка срока попадает на этикетку
- THEN печатается день и время без года и без подписи — `09.09 16:04`
- AND время показывается в часовом поясе пользователя

#### Scenario: Печатный номер сокращён

- GIVEN заказ `RO2026-0342`
- WHEN формируется этикетка
- THEN крупным шрифтом печатается только `0342` — та часть, которую называют вслух

#### Scenario: Содержимое QR

- GIVEN заказ `RO2026-0342`
- WHEN формируется QR-код
- THEN он содержит **полный** номер `RO2026-0342`, без URL и префиксов
- AND сокращённый печатный номер на содержимое QR не влияет: иначе `0342` повторялся бы
  каждый год и сканер находил бы чужой заказ

#### Scenario: Читаемость на дешёвой термобумаге

- GIVEN этикетка печатается на плохой ленте
- WHEN формируется изображение
- THEN все строки набраны жирным начертанием

#### Scenario: Строки подгоняются под ширину ленты

- GIVEN на этикетке столько строк, что при крупном шрифте они не помещаются
- WHEN подбираются размеры шрифтов
- THEN кегль уменьшается, пока номер и все строки не уложатся в ширину ленты
- AND длина этикетки на количество строк не влияет: она расширяет колонки, а не добавляет места по высоте

#### Scenario: Длинные значения не ломают вёрстку

- GIVEN клиент с названием длиннее, чем помещается в две строки
- WHEN формируется этикетка
- THEN название обрезается по ширине с многоточием
- AND размер шрифта номера подбирается так, чтобы номер помещался целиком

#### Scenario: Заказ без клиента

- GIVEN заказ, у которого не заполнен клиент
- WHEN формируется этикетка
- THEN этикетка формируется без ошибки, строка клиента пропускается

### Requirement: Формат выдачи этикетки

Модуль отдаёт растр, а не PDF: принтер не имеет драйвера и принимает битмап внутри
TSPL-команды.

#### Scenario: Предпросмотр

- GIVEN пользователь с правом чтения заказа
- WHEN он запрашивает этикетку как изображение
- THEN отдаётся однобитный PNG в ориентации «как читает человек»

#### Scenario: Поток для принтера

- GIVEN тот же заказ
- WHEN запрашивается TSPL-поток
- THEN отдаётся `SIZE`, `GAP`, `DIRECTION`, `DENSITY`, `CLS`, `BITMAP`, `PRINT 1`
- AND растр повёрнут на 90° под узкую головку
- AND биты инвертированы: 0 = чёрная точка

#### Scenario: Права доступа

- GIVEN пользователь без доступа к заказу
- WHEN он запрашивает этикетку этого заказа
- THEN запрос отклоняется

### Requirement: Поиск заказа сканером

Сканирование этикетки должно приводить к заказу без дополнительного обучения персонала.

#### Scenario: Сканирование в строку поиска

- GIVEN 2D-имиджер в режиме USB-HID
- WHEN этикетка отсканирована при фокусе в строке поиска списка заказов
- THEN в поиск подставляется `RO2026-0342` и находится нужный заказ

#### Scenario: Сканирование в списке заказов открывает заказ

- GIVEN открыт список заказов
- WHEN этикетка отсканирована, фокус при этом не в поле ввода
- THEN открывается форма того заказа, чей номер записан в QR

#### Scenario: Чужой штрихкод игнорируется

- GIVEN открыт список заказов
- WHEN отсканирован код, не похожий на номер заказа
- THEN ничего не происходит, ошибка не показывается

#### Scenario: Номер есть, а заказа нет

- GIVEN отсканирован номер в формате заказа, которого нет в базе
- WHEN обработчик не находит запись
- THEN показывается ненавязчивое предупреждение, список остаётся открытым
