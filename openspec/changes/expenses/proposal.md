# Proposal: Expenses — Расходы мастерской

## Intent

Учёт операционных расходов мастерской для P&L анализа.
Доходная часть уже есть (биллинг → инвойсы → платежи, остаток кассы/банка в `Cash & Bank`).
Нужна расходная часть — удобный ввод расходов и итоговая строка прибыли.

## Approach

### Быстрый расход — кастомный документ-оркестратор

Стандартный Vendor Bill для повседневных трат тяжёл (поставщик обязателен, два шага).
Решение: модель `jewelry.expense.entry` — одноэкранный документ расхода.

Поля: дата, **статья расхода**, сумма, журнал оплаты (касса/банк), поставщик (опц.), заметка.
Кнопка **Post** создаёт и постит `account.move` (`move_type='entry'`, `journal_id` = выбранный журнал):
- DR: expense account выбранной статьи
- CR: счёт по умолчанию журнала кассы/банка

Кассовый метод: расход сразу уменьшает остаток кассы/банка. Кнопка **Cancel** удаляет проводку.

### Статьи расходов = предопределённые expense accounts

Категории расхода = `account.account` (`account_type='expense'`, коды `EXP*`):
Rent, Tools, Consumables, Purchases, Payroll, Other Expenses.

**Зарплаты — это статья EXP500 Payroll в том же документе**, отдельного документа payroll нет.

Счета создаются **программно** (`_ensure_expense_accounts`): post_init_hook + ленивое создание
при открытии экрана Expenses. Статический XML не годится — `account.account` из XML удаляются
при загрузке плана счетов.

### Vendor Bills — стандартный Odoo (для кредиторки)

Счета поставщиков с отсрочкой ведутся стандартным Vendor Bill (`account.move`, `in_invoice`)
через отдельный пункт меню. Кастома нет. Оба источника (быстрые расходы + vendor bills) постятся
на expense accounts → единый запрос для P&L.

### KPI Dashboard — P&L секция

Расширение существующего дашборда:
- Секция **Expenses** — строки по expense accounts, текущий/прошлый месяц
- Строка **Net Profit** = Revenue − Total Expenses (красным при отрицательном)

## Модуль

`jewelry_expenses` — зависит от: `jewelry_repair_base`, `account`

## Scope

### В scope
1. Предопределённые expense accounts (через `_ensure_expense_accounts`)
2. Документ быстрого расхода `jewelry.expense.entry` (касса/банк, проводка, отмена)
3. Меню: Expenses / Vendor Bills (стандарт) / Expense Categories
4. Расширение KPI Dashboard: секция Expenses + Net Profit

### Вне scope
- Отдельный документ зарплат (зарплата = статья EXP500 в быстром расходе)
- Поле monthly_salary на исполнителе
- Бюджетирование и лимиты по категориям
- Привязка расходов к конкретным заказам
- Vendor Bills UI-кастомизации (используется as-is)
