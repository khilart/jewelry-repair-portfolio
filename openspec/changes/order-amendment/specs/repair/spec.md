# Delta for Repair / Order

## ADDED Requirements

### Requirement: Порог редактирования заказа — выдача

До выдачи заказ правится свободно. После выдачи любое изменение содержимого возможно
только через режим правки.

#### Scenario: Заказ до выдачи

- GIVEN заказ в состоянии `draft`, `in_progress` или `ready`
- WHEN пользователь меняет услуги, материалы, камни или цены
- THEN изменения сохраняются без дополнительных действий

#### Scenario: Выданный заказ заблокирован

- GIVEN заказ в состоянии `delivered`, режим правки не открыт
- WHEN пользователь пытается изменить содержимое заказа
- THEN изменение отклоняется с указанием, что нужно открыть заказ для правки

#### Scenario: Проверка вынесена из write

- GIVEN любая точка кода, меняющая содержимое заказа
- WHEN она пишет в заказ или напрямую в строки услуг, материалов, камней
- THEN она вызывает `_check_editable()` на заказе
- AND проверка не зависит от того, прошла ли запись через `order.write`

---

### Requirement: Кнопка «Открыть для правки»

Единственная точка входа для изменения выданного заказа.

#### Scenario: Кнопка доступна только на выданном заказе

- GIVEN заказ в состоянии `delivered`
- WHEN режим правки ещё не открыт
- THEN кнопка «Открыть для правки» отображается в форме заказа

#### Scenario: Обязательная причина

- GIVEN пользователь нажал «Открыть для правки»
- WHEN открывается диалог подтверждения
- THEN диалог перечисляет документы, которые будут отменены
- AND требует заполнить причину
- AND без причины действие не выполняется

#### Scenario: Заказ остаётся выданным

- GIVEN заказ открыт для правки
- WHEN пользователь меняет содержимое заказа
- THEN `state` остаётся `delivered` на всём протяжении правки
- AND документ выдачи не отменяется и не изменяется
- AND заказ не появляется в очереди кандидатов на выдачу

#### Scenario: Право на действие

- GIVEN пользователь без роли менеджера
- WHEN он открывает форму выданного заказа
- THEN кнопка «Открыть для правки» недоступна

---

### Requirement: След режима правки

Открытый режим правки виден на заказе и фиксируется в истории.

#### Scenario: Плашка на заказе

- GIVEN заказ открыт для правки
- WHEN пользователь открывает форму заказа
- THEN отображается плашка «Открыт для правки» с причиной, автором и датой

#### Scenario: Запись в чаттер

- GIVEN пользователь подтвердил открытие для правки
- WHEN действие выполняется
- THEN в чаттер заказа записывается причина, автор и перечень отменённых документов
- AND в чаттер биллинга и счёта записывается та же причина
- AND номер отменённого счёта фиксируется в чаттере, так как `batch.invoice_id` обнуляется

#### Scenario: Возврат к пересборке

- GIVEN заказ открыт для правки и относится к откаченному биллингу
- WHEN пользователь открывает форму заказа
- THEN отображается баннер со ссылкой на биллинг, ожидающий пересборки

#### Scenario: Снятие флага

- GIVEN заказ открыт для правки
- WHEN биллинг, включающий этот заказ, подтверждён заново
- THEN флаг и плашка снимаются автоматически

---

### Requirement: Защита выданного заказа от косвенных изменений

Действия, меняющие содержимое заказа в обход формы, подчиняются тому же порогу.

#### Scenario: Пересчёт котировки металла на выданном заказе

- GIVEN заказ в состоянии `delivered`, режим правки не открыт
- WHEN пользователь нажимает кнопку применения котировки металла к материалам
- THEN действие отклоняется
- AND цены строк материалов не изменяются
