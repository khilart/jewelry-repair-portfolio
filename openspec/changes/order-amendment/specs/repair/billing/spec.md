# Delta for Repair / Billing

## ADDED Requirements

### Requirement: Откат биллинга и счёта при открытии заказа для правки

Глубина отката определяется состоянием заказа, а не выбором пользователя.

#### Scenario: Выдан, не отбиллен

- GIVEN заказ `delivered` без `billing_batch_id`
- WHEN пользователь открывает заказ для правки
- THEN ни один документ не отменяется
- AND заказ помечается флагом правки и снимается замок

#### Scenario: Отбиллен, счёта нет

- GIVEN заказ входит в подтверждённый биллинг, счёт не создан
- WHEN пользователь открывает заказ для правки
- THEN биллинг отменяется и переводится в черновик
- AND транзакции списания металла со счёта клиента снимаются, баланс восстанавливается
- AND `billing_batch_id` на заказе очищается

#### Scenario: Есть счёт

- GIVEN заказ входит в подтверждённый биллинг, по которому создан счёт
- WHEN пользователь открывает заказ для правки
- THEN счёт отменяется, затем отменяется биллинг
- AND диалог подтверждения перечисляет номер счёта и номер биллинга до выполнения

#### Scenario: Предупреждение об оплаченном счёте

- GIVEN счёт проведён и оплачен полностью или частично
- WHEN пользователь открывает диалог подтверждения
- THEN диалог предупреждает, что сверка с платежом будет снята
- AND что платёж останется неразнесённым до привязки к новому счёту

---

### Requirement: Сохранение зачёта металла при откате

`client_metal_debit_fine` — вводимое вручную поле, а сброс биллинга в черновик пересоздаёт
строки. Значение должно пережить откат и быть подтверждено при пересборке.

#### Scenario: Зачёт переносится

- GIVEN биллинг с заполненным `client_metal_debit_fine` по строкам
- WHEN биллинг откатывается для правки заказа
- THEN введённые значения зачёта сохраняются и восстанавливаются в строках черновика

#### Scenario: Подтверждение зачёта после правки

- GIVEN заказ был изменён, биллинг пересобирается
- WHEN пользователь подтверждает биллинг
- THEN отображается прежнее значение зачёта и пересчитанный максимум
- AND подтверждение требуется явно, если зачёт превышает новый максимум

---

### Requirement: Пересборка счёта

Пересборка выполняется пользователем вручную, автоматизация подтверждения биллинга
не допускается.

#### Scenario: Пересборка после правки

- GIVEN заказ поправлен, биллинг в состоянии черновика
- WHEN пользователь подтверждает биллинг и создаёт счёт
- THEN счёт собирается из текущего содержимого заказов
- AND после создания открывается форма счёта для привязки оплаты

#### Scenario: Выбор заказов сохраняется

- GIVEN биллинг откачен и переведён в черновик
- WHEN пользователь открывает биллинг
- THEN ранее выбранные заказы остаются выбранными
- AND заказы остаются в состоянии `delivered`, поэтому не выпадают из кандидатов

#### Scenario: Незавершённая правка видна

- GIVEN биллинг откачен и не пересобран
- WHEN руководитель просматривает список биллингов
- THEN такие биллинги отличимы от обычных черновиков

---

### Requirement: Навигация по цепочке документов

Независимая часть изменения: сделать видимым состав документов и связь с оплатой.

#### Scenario: Состав счёта

- GIVEN открыт счёт, созданный из биллинга
- WHEN пользователь смотрит на форму счёта
- THEN доступен переход к биллингу, из которого счёт собран

#### Scenario: Состав биллинга

- GIVEN открыт биллинг
- WHEN пользователь смотрит на форму биллинга
- THEN доступны переходы к заказам и к документам выдачи, из которых он состоит

#### Scenario: Платёж по заказу

- GIVEN заказ отбиллен и счёт оплачен
- WHEN пользователь открывает заказ
- THEN доступен переход к платежам, которыми оплачен счёт
