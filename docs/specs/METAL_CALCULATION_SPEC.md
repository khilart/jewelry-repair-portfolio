# Спецификация: Автоматический расчёт расхода металла

## Статус: Архитектура утверждена, готово к реализации

---

## Бизнес-логика

Изделие взвешивается при приёмке и при выдаче. В процессе работы:
- Могут быть вставлены камни (увеличивают вес изделия)
- Может быть добавлен металл (пайка, изменение размера)
- Часть металла теряется при полировке, обпиле, закрепке (стружка, пыль, крапаны)

Система должна рассчитать:
1. **Сколько металла добавила мастерская** — расход со склада
2. **Возвратные потери** — стружка, опилки, крапаны (подлежат сбору мастером)
3. **Безвозвратные потери** — пыль, угар (не восстанавливаются)

---

## Уравнение баланса

```
вес_получен + металл_добавлен + вес_камней = вес_выдан + потери_всего

потери_всего = возвратные + безвозвратные
```

Откуда:
```
металл_добавлен = (вес_выдан - вес_получен - вес_камней) + потери_всего
```

---

## Единица измерения

Все расчёты ведутся в **граммах сплава** (вес сплава, не чистого металла).  
Перевод в чистый металл выполняется в отчётах по формуле:
```
чистый_металл_г = вес_сплава_г × alloy.purity
```

---

## Коэффициенты потерь

Хранятся на **шаблоне операции** (`jewelry.repair.operation`):

| Поле | Описание |
|------|----------|
| `loss_recoverable_percent` | % возвратных потерь от веса изделия при приёмке |
| `loss_irrecoverable_percent` | % безвозвратных потерь от веса изделия при приёмке |

Примеры:
- Полировка: 0.1% возвратные, 0.2% безвозвратные
- Закрепка: 0.05% возвратные (откушенные крапаны), 0.0% безвозвратные
- Изменение размера: 0.3% возвратные (опилки), 0.1% безвозвратные

---

## Расчёт потерь — на уровне операции

Потери рассчитываются и фиксируются **по каждой операции отдельно** для полной трассируемости.

```
база = received_weight  (вес изделия при приёмке)

возвратные_г = база × operation.loss_recoverable_percent / 100
безвозвратные_г = база × operation.loss_irrecoverable_percent / 100
```

Это даёт:
- Видно вклад каждой операции в суммарные потери
- Легко расширить: добавить `weight_after_g` на операцию и пересчитать от фактического веса

## Флаг добавления металла

На заказе: **`metal_was_added`** (Boolean)

- `False` (по умолчанию) — металл не добавлялся, работа только с исходным изделием
- `True` — мастерская добавляла металл (пайка, вставка при изменении размера и т.п.)

Если `False`:
```
потери_всего = вес_получен + вес_камней - вес_выдан
(безвозвратные и возвратные распределяются пропорционально коэффициентам)
```

Если `True`:
```
металл_добавлен = (вес_выдан - вес_получен - вес_камней) + Σ потери по операциям
```

## Модель хранения потерь (утверждено)

Оба типа потерь фиксируются как **движения металла** (`jewelry.metal.move`) на склад исполнителя операции.

В `jewelry.metal.move` добавляется поле `loss_type`:

| Значение | Описание |
|----------|----------|
| `none` | Обычное движение (не потеря) |
| `recoverable` | Возвратные потери (стружка, опилки, крапаны) |
| `irrecoverable` | Безвозвратные потери (пыль, угар) |

**Ключевые правила:**
- Потери фиксируются по сплаву заказа
- Оба типа идут на склад исполнителя конкретной операции
- В отчёт мастера по балансу металла потери **не попадают** (фильтруются по `loss_type`)
- Аналитика потерь (сколько, какой тип, за период, по мастеру) — через группировку `metal.move`

**За рамками MVP:** физическая сдача опилок мастером менеджеру, сверка фактического веса, акт приёмки смешанного лома.

---

## Генерируемые движения металла

При нажатии кнопки **"Calculate Metal"** на заказе:

| # | Тип движения | `loss_type` | Условие | Storage |
|---|-------------|-------------|---------|---------|
| 1 | `weight_out` | `none` | `metal_was_added = True` | Склад мастерской → (расход) |
| 2 | `weight_out` | `recoverable` | Σ возвратных > 0 | Склад исполнителя операции |
| 3 | `weight_out` | `irrecoverable` | Σ безвозвратных > 0 | Склад исполнителя операции |

---

## Защита от двойного расчёта

Флаг `metal_calculated` (Boolean) на заказе:
- После нажатия "Calculate Metal" выставляется в `True`
- Кнопка скрывается / блокируется
- Повторный расчёт — только через явный сброс (роль менеджера)
