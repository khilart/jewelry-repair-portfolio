# Olympia P22 — протокол печати этикеток

Результат реверс-инжиниринга 2026-09-08. Источник истины — перехват реального сеанса
печати фирменного приложения Labelize с Android (Bluetooth HCI snoop log).

## Что за принтер

Olympia P22 — компактный термопринтер этикеток. Лента до 15 мм, 203 dpi, 30 мм/с.
Фирменный путь печати — приложение Labelize по Bluetooth. Драйвера для настольных ОС
не существует, поэтому печатать можно только отправкой готового потока команд.

## Два радио

У принтера два независимых Bluetooth-интерфейса с разными адресами:

| | Классический (SPP) | BLE |
|---|---|---|
| Пример адреса | `F0:4E:4B:15:19:64` | `D0:29:7F:8A:3F:B4` |
| Сервисы | `0x1101` (Serial Port Profile) | `AE00`, `AE3A`, `FF00` |
| Язык | **TSPL, открытым текстом** | свой кадрированный протокол |
| Кто использует | приложение на Android | приложение на iOS |

**Канал печати — классический SPP.** На нём приложение шлёт обычный текстовый TSPL.
Именно этот путь реализован в модуле `jewelry_repair_label`.

**BLE разобран не полностью.** Характеристики: `AE01` — запись, `AE02` — уведомления
(`FF02`/`FF04` тоже доступны на запись). Хендшейк снят: команда `00` + 19 нулевых байт
возвращает `01` и 16 байт идентификатора устройства, команда `01` + 19 нулей возвращает
`02 "pass"` — то есть пароль пустой. Дальше формат неизвестен: ни TSPL, ни ESC/POS, ни
побайтовый реплей SPP-потока в этот канал не проходят. Для разбора нужен перехват с iOS.

## Формат печати (SPP)

Полная программа печати одной этикетки:

```
BATTERY?\r\n            ← служебные запросы приложения, для печати не обязательны
ESC ! o \r\n
CONFIG?\r\n
...
SIZE 14.0 mm,35.0 mm\r\n
GAP 8.0 mm,0 mm\r\n
DIRECTION 0,0\r\n
DENSITY 4\r\n
CLS\r\n
BITMAP 0,8,12,264,1,<3168 байт растра>\r\n
PRINT 1\r\n
```

`BATTERY?` — единственная команда, на которую принтер отвечает (`BATTERY u`). Удобна как
проверка живости канала.

### Геометрия

- Головка печатает **96 точек поперёк ленты** = 12 мм при 203 dpi, хотя лента 14 мм:
  по краям остаётся непечатаемая полоса.
- Длина идёт **по подаче**. Для этикетки 35 мм это 280 точек, из них 8 сверху и 8 снизу —
  поля, растр занимает 264.
- `BITMAP x,y,ширина_в_байтах,высота_в_точках,режим,данные`. Ширина задаётся в байтах,
  поэтому кратна восьми.

### Зазор и непрерывная лента

`GAP` задаёт промежуток между высеченными этикетками — по нему принтер отсчитывает
следующую. **На непрерывной ленте зазор должен быть `0`**, иначе после печати принтер
продолжает гнать пустую ленту, пока не упрётся в таймаут поиска несуществующего
промежутка. Проверено 2026-09-09 на Windows.

### Растр

- Изображение печатается **повёрнутым на 90°**: макет рисуется горизонтально, как читает
  человек, и поворачивается при упаковке.
- **0 = чёрная точка.** Биты инвертированы относительно обычного растра: у почти белой
  этикетки около 98% единиц.

## Ограничение macOS

Печать подтверждена, но повторяемости на Mac добиться не удалось. Поведение:

- порт `/dev/cu.P22` появляется при сопряжении классического радио;
- RFCOMM-канал поднимается **только при первом обращении после сопряжения** — индикатор
  принтера синеет, этикетка печатается, после закрытия порта линк рвётся;
- повторное открытие порта линк уже не поднимает, при этом запись проходит без ошибок и
  данные молча теряются;
- оживает только пересопряжением устройства.

Отдельная ловушка: блокирующая запись в такой порт может навсегда застрять в драйвере —
процесс не снимается даже `kill -9` и держит канал до обрыва линка. Писать нужно
неблокирующе, через `select` с дедлайном.

**На Windows печать работает** (проверено 2026-09-09): сопряжение создаёт постоянный
COM-порт, печать из браузера идёт повторно без пересопряжения. Значит одноразовость
канала — свойство macOS, а не принтера.

## Как проверить канал вручную

```bash
# на macOS, сразу после сопряжения
python3 -c "
import os
fd = os.open('/dev/cu.P22', os.O_RDWR | os.O_NOCTTY | os.O_NONBLOCK)
os.write(fd, open('label.tspl','rb').read())
"
```

Готовый поток отдаёт сам модуль: `/jewelry/repair/label/<id>.tspl`.
