# LOSS_ACCOUNTING_SPEC.md

Спецификация контура учёта нормативных потерь металла.

---

## Цель

Автоматически фиксировать нормативные потери металла (стружка, угар) в момент завершения операции.

Мастер вводит только вес израсходованного металла — система сама рассчитывает и записывает потери в регистр. Регистр используется руководителем для отчёта о плановых потерях по хранилищам и мастерам.

---

## Источник данных

Потери рассчитываются из `jewelry.repair.material.line`:

| Поле | Откуда |
|------|--------|
| `weight_loss` | вычисляется как `weight × return_loss_percent / 100`, хранится в строке |
| `alloy_id` | сплав материала |
| `order_operation_id` | операция заказа |
| `executor_id.metal_storage_id` | хранилище мастера (через операцию) |

Процент потерь (`return_loss_percent`) хранится в карточке продукта (`product.template`), по умолчанию 10%.

---

## Новая модель: `jewelry.metal.loss`

Плоский регистр строк — по аналогии с `jewelry.metal.move`.

### Поля

| Поле | Тип | Описание |
|------|-----|---------|
| `name` | Char | Автономер из sequence, readonly |
| `loss_date` | Datetime | Дата фиксации, default=now |
| `company_id` | Many2one → res.company | Компания |
| `alloy_id` | Many2one → jewelry.metal.alloy | Сплав |
| `metal_id` | Many2one → jewelry.metal, related | Металл (через сплав) |
| `weight_loss` | Float (16.3) | Вес потерь в граммах |
| `storage_id` | Many2one → jewelry.metal.storage | Хранилище мастера |
| `source_operation_id` | Many2one → jewelry.repair.order.operation | Операция-источник |
| `source_repair_order_id` | Many2one → jewelry.repair.order, related | Заказ (через операцию) |
| `source_material_line_id` | Many2one → jewelry.repair.material.line | Строка материала-источник |

Все поля readonly — регистр не редактируется вручную.

---

## Логика создания записей

Записи создаются в методе `action_mark_done` модели `jewelry.repair.order.operation` — в тот же момент что и `jewelry.metal.move` (writeoff документ).

**Условия создания записи:**
- `material_line.consume_from_stock = True`
- `material_line.alloy_id` заполнен
- `material_line.weight_loss > 0`
- `executor_id.metal_storage_id` заполнен (иначе `UserError`)

**Одна строка материала → одна запись в регистре.**

---

## Отмена

Если операция отменяется после завершения — записи потерь удаляются (cascade через `source_operation_id` или явная очистка в логике отмены).

> Уточнить: есть ли сценарий отмены завершённой операции в текущей логике.

---

## Отчётность

Регистр позволяет получить:
- суммарные потери по хранилищу за период
- суммарные потери по сплаву за период
- суммарные потери по заказу
- детализацию по операциям и строкам материалов

Форма отчёта — отдельная задача, в MVP достаточно списка с группировкой.

## Размещение

## Вне scope MVP

- Сравнение фактических потерь с нормативными
- Учёт собранной стружки как отдельного прихода лома
- Разделение возвратных и невозвратных потерь (`non_return_loss_percent` в модели продукта существует, но в регистре пока не используется)
