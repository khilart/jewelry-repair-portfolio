# ТЗ: внутренняя печатная форма заказа ремонта

## 1. Назначение

Добавить во внутренний контур Odoo печатную форму для заказа ремонта (`jewelry.repair.order`), предназначенную для сотрудников мастерской.

Документ используется:
- при приемке изделия
- при передаче заказа в работу
- как бумажная карточка сопровождения заказа внутри мастерской

Печатная форма не является клиентской квитанцией и не предназначена для внешней выдачи клиенту.

## 2. Объект печати

Модель:
- `jewelry.repair.order`

Источник данных:
- текущая запись заказа ремонта

## 3. Точка запуска

В интерфейсе заказа должна появиться функция печати:
- кнопка `Print` / `Печать` в форме заказа
- результатом должен быть стандартный Odoo PDF-отчет

Ожидаемое поведение:
- печать доступна из карточки одного заказа
- 1 заказ = 1 PDF-документ

## 4. Формат документа

Базовый формат:
- PDF
- A4
- портретная ориентация

Первая версия должна быть рассчитана на обычную офисную печать без специальных этикеток, QR и штрихкодов.

## 5. Тип документа

Это внутренняя печатная форма.

Документ должен содержать рабочую информацию для сотрудников:
- идентификацию заказа
- идентификацию изделия
- состав услуг и операций
- ключевые производственные и приемочные данные

Документ не должен содержать коммерческий блок с ценами.

## 6. Состав данных в печатной форме

В шапке документа:
- номер заказа
- статус заказа
- клиент
- дата приемки
- срок исполнения

Основной блок по изделию:
- тип изделия
- количество
- описание изделия
- признак `New Product Manufacturing`, если поле установлено
- фото изделия, если загружено

Блок металла и веса:
- сплав (`alloy_id`)
- металл, если выводится через related из сплава
- вес при приемке (`received_weight`)
- вес при выдаче (`delivered_weight`), если уже заполнен
- разница веса (`weight_delta`), если доступна
- эквивалент чистого металла на приемке (`fine_weight_received`), если доступен
- эквивалент чистого металла на выдаче (`fine_weight_delivered`), если доступен

Блок услуг:
- список услуг из `service_line_ids`
- наименование услуги
- описание строки услуги
- количество

Цены в этот блок не включать:
- не печатать `price_unit`
- не печатать `subtotal`
- не печатать `amount_total`

Блок операций:
- список операций заказа из `order_operation_ids`
- порядок / `sequence`
- наименование операции
- плановый исполнитель (`executor_id`), если есть
- назначенный пользователь (`assigned_user_id`), если есть
- статус операции
- плановая дата (`planned_date`), если есть

Блок внутренних данных:
- внутренние заметки заказа (`notes`) печатать
- при желании можно печатать `current_holder_user_id` и текущее местоположение как внутреннюю служебную информацию, но это лучше оставить опциональным
- в первую версию рекомендовано не включать служебный блок движения, чтобы форма не перегружалась

## 7. Что не включать

В первую версию не включать:
- цены
- сумму заказа
- `billing batch`
- `invoice`
- `delivery document`
- подписи
- QR-код
- штрихкод
- историю изменений
- технические служебные поля Odoo

## 8. Правила отображения

Если данные отсутствуют:
- пустые необязательные поля не должны ломать макет
- фото не показывать, если его нет
- блок операций должен печататься даже если список пуст
- блок внутренних заметок показывать только если заметки заполнены

Если операции еще не сгенерированы:
- печатная форма все равно должна строиться
- в блоке операций должен быть пустой список или понятная внутренняя пометка без ошибки рендера

Если заказ в статусе `cancel`:
- печать не запрещается
- в документе должен выводиться фактический статус заказа

## 9. Права доступа

Печатная форма должна наследовать доступ к заказу:
- пользователь, который может открыть заказ, может запустить печать
- дополнительных отдельных ролей под печать не требуется

## 10. UI-требование

В форме заказа должна быть предусмотрена кнопка печати в header.

Ожидаемое название:
- `Print`
или
- `Печать`

Рекомендация:
- использовать стандартный Odoo report action, чтобы документ появлялся и в меню печати

## 11. Ограничения первой версии

Первая версия не решает задачи:
- печати бирки
- печати этикетки с крупным номером
- печати QR
- клиентской квитанции
- отдельного компактного production slip

Это отдельные будущие доработки.

## 12. Критерии приемки

Функция считается реализованной корректно, если:
- из карточки заказа можно открыть PDF печатной формы
- PDF строится без ошибок для заказа с минимально заполненными обязательными полями
- PDF корректно строится для заказа с фото, услугами и операциями
- в документе отсутствуют цены и суммы
- в документе печатаются внутренние заметки
- пустые необязательные поля не ломают верстку
- один заказ печатается как один самостоятельный документ

## 13. Редакционное решение

В шапке документа номер заказа должен быть самым заметным визуальным элементом.
